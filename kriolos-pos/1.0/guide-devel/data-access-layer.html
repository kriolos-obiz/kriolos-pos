Database Access Layer

Architecture and lifecycle of database sessions, sentences, and transactional execution in KriolOS POS.

1. Core Persistence Components (kriolos-opos-base)

The data access layer in KriolOS POS is built upon low-overhead JDBC abstractions that avoid the performance penalties of full Object-Relational Mappings (ORM):

  • com.openbravo.data.loader.Session: Encapsulates database connectivity and transaction state flags (begin(), commit(), rollback()).

  • com.openbravo.data.loader.Transaction<T>: Template pattern executing atomic multi-table business operations wrapped in a database transaction.

  • com.openbravo.data.loader.PreparedSentence: Type-safe, parameterized SQL statement execution leveraging JDBC PreparedStatement to prevent SQL injection.

  • com.openbravo.data.loader.SequenceGeneric: Thread-safe sequence generator for sequential ticket and invoice IDs.
